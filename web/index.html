4 Inyección de dependencias: AppContext

AppContext es un singleton que crea todas las piezas una sola vez y las guards en un Map<Class<?>, Object>.

private AppContext() {
    DatabaseConfig.init();          // abre el pool de conexiones
    registrarRepositorios();
    registrarServicios();
    registrarControladores();
}

Cuando JavaFX carga un FXML, se usa:

loader.setControllerFactory(AppContext.getInstance()::getBean);

Eso significa: “cuando el FXML necesite un controlador, pídeselo a AppContext”, que ya lo tiene con sus servicios inyectados por constructor.

7 Los 4 pilares de la POO (con código real)

7.1 Encapsulamiento

Ocultar los datos internos y exponer solo métodos controlados.

private Long idPago;                 // campo privado
private BigDecimal monto;
// Lombok genera getMonto() / setMonto(...)
public String getMontoTexto() {      // lógica de formato encapsulada
    return "S/ " + String.format(Locale.US, "%,.2f", monto);
}

Sesion guarda private static Usuario actual y solo permite iniciar(), actual(), cerrar(). Repository esconde el SQL: el controller nunca ve un PreparedStatement.

7.2 Abstracción

Mostrar solo lo esencial: trabajar con interfaces sin importar la implementación.

public interface ICrudGenericoRepository<T, ID> {
    T save(T entity);
    T update(T entity);
    Optional<T> findById(ID id);
    List<T> findAll();
    void deleteById(ID id);
    boolean existsById(ID id);
}

El controller usa IDepartamentoService, no DepartamentoServiceImp. App abstrae JavaFX: el resto del programa solo llama mostrarLogin() / mostrarPrincipal().

7.3 Herencia

Reutilizar comportamiento común en una clase base.

public abstract class AbstractJpaRepository<T, ID>
        extends SqlHelper<T>
        implements ICrudGenericoRepository<T, ID> {

    protected abstract String getTableName();
    protected abstract String getPkColumn();
    protected abstract T insert(Connection c, T e) throws SQLException;

    @Override public T save(T entity) { /* transacción + commit/rollback */ }
}

Cada repositorio concreto (DepartamentoRepository, PagoRepository…) extends esa clase y solo define nombre de tabla, PK e insert/updateRow. Otras herencias: App.Ventana extends Application, BusinessException extends RuntimeException.

7.4 Polimorfismo

Una misma interfaz, distintas implementaciones; el código que la usa no cambia.

loader.setControllerFactory(AppContext.getInstance()::getBean);
// getBean(IContratoService.class) devuelve ContratoServiceImp
// getBean(IPagoService.class)     devuelve PagoServiceImp

También aparece al sobrescribir updateItem() en las celdas de tabla (Celdas, celdaDinero(), celdaFecha()): JavaFX llama al método de la subclase aunque la referencia sea TableCell.

Tabla: dónde está cada pilar

PilarArchivos donde se veQué puedes decir
Encapsulamientomodel/*.java, Sesion, repository/*“Los campos son privados y solo se accede con métodos”
Abstracciónservice/*.java, repository/ICrudGenericoRepository, App“Programo contra interfaces, no contra implementaciones”

10 Supabase explicado

Supabase es PostgreSQL como servicio: base de datos + API REST (PostgREST) + autenticación. Proyecto: https://zarbbelqcsivzhjrpguu.supabase.co.

Escritorio (JDBC directo)

jdbc:postgresql://aws-0-us-east-1.pooler.supabase.com:5432/postgres
     ?sslmode=require&prepareThreshold=0
  • sslmode=require: Supabase no acepta conexiones sin cifrar.
  • prepareThreshold=0: el pooler en modo transacción no conserva sentencias preparadas.
  • Usuario: postgres.<project-ref>; clave: solo en variables de entorno.
  • ddl.auto=false y seed.demo=false: no se ejecuta el esquema encima de Supabase.

APK (REST, no JDBC)

GET   /rest/v1/departamento?select=*
POST  /rest/v1/pago
PATCH /rest/v1/pago?idpago=eq.9
DELETE /rest/v1/pago?idpago=eq.9
Headers: apikey / Authorization: Bearer <anon key>

Android no puede usar JDBC/HikariCP. La anon key es pública; la seguridad real son las políticas RLS creadas en database/supabase_movil_policies.sql.

Nunca pongas la sb_secret_… en el APK: saltea RLS. Si se compartió, rótala en el dashboard.

11 Interfaz: FXML, CSS y Scene Builder

FXML = estructura (qué controles y dónde). CSS = apariencia (colores, bordes, sombras). Controller = comportamiento (qué pasa al hacer clic).

En los FXML hay styleClass="modulo", card, nav-button, boton-primario, etc. Esos nombres son “ganchos” que app.css usa.

El resaltado azul del sidebar NO está en el FXML: los iconos <SVGPath> sí están en main.fxml, pero la clase nav-button-activo la añade en tiempo de ejecución MainController.marcarBotonActivo() y es app.css la que la pinta azul. Por eso en Scene Builder los botones se ven grises: está viendo el FXML estático, sin Java ni CSS aplicados.
¿Por qué Scene Builder se ve gris y sin datos? Porque Scene Builder no ejecuta los controladores ni aplica por defecto el CSS de la app. Ahora cada FXML declara stylesheets="@../css/app.css" para que el preview cargue los estilos. La tabla seguirá diciendo “No content in table” hasta que initialize() consulta la base.

Pantallas

  • login.fxml: tarjeta sobre degradado, logo, campos y botón principal.
  • main.fxml: sidebar con iconos SVG + cabecera con usuario + StackPane de contenido.
  • Módulos: buscador arriba, tarjeta de formulario y tarjeta de tabla.
  • Chips de estado: verde = disponible, rojo = ocupado, azul = vigente, gris = finalizado.

14 Seguridad y credenciales

  • La clave de Supabase se lee de variables SUPABASE_DB_*, no del código.
  • database/Coenction.txt está ignorado por git (contiene la clave real).
  • La anon key del APK es pública; la protección son las políticas RLS.
  • La secret key sb_secret_… nunca se usa en el cliente y debería rotarse.
  • Las contraseñas de usuario están en texto plano por ser proyecto académico; en producción irían con hash BCrypt.

20 Generics: ¿qué significa <T, ID>?

Los generics permiten escribir una clase una sola vez y especializarla con tipos concretos. Es como un molde: tú pones el tipo.

public abstract class AbstractJpaRepository<T, ID> extends SqlHelper<T> { … }
  • T = tipo de la entidad (Departamento, Pago, Contrato…).
  • ID = tipo de la llave primaria (aquí siempre Long).

Sustitución real

Clase concretaTIDMétodo resultante
DepartamentoRepository extends AbstractJpaRepository<Departamento, Long>DepartamentoLongOptional<Departamento> findById(Long id)
PagoRepository extends AbstractJpaRepository<Pago, Long>PagoLongList<Pago> findAll()
ICrudGenericoRepository<T, ID>variablevariablecontrato genérico compartido

Gracias a esto, el método findById(ID id) escrito una sola vez sirve para todas las tablas, y el compilador garantiza que PagoRepository devuelva Pago, no cualquier cosa.

Ventaja: evita duplicar el código del CRUD 7 veces y evita Cast peligrosos. Es el mismo principio que List<Pago>: una lista “tipada”.

Otros generics del proyecto: ObservableList<Pago>, FilteredList<Contrato>, TableColumn<Pago, BigDecimal>, Callback<TableColumn<S,T>, TableCell<S,T>> en Celdas, Optional<Usuario>.

21 Cómo viaja un dato (ejemplo completo)

Sigue un departamento desde que el usuario escribe “101” hasta que aparece en la tabla.

Vuelta de ida: del texto a la fila de la base

1
TextField txtNumero contiene el String "101".
2
DepartamentoController.onGuardar() llama a Formato.decimal(txtPrecio.getText()) → BigDecimal(650.00) y arma un Departamento con numero="101", piso=1, etc.
3
DepartamentoServiceImp.save(): normalizar() recorta espacios; Validador.validar() comprueba anotaciones; validarNumeroUnico() consulta findByNumero; fuerza idDepartamento=null y estado DISPONIBLE.
4
DepartamentoRepository.insert(Connection, Departamento) ejecuta INSERT INTO departamento (...) VALUES (?, ?, ?, ?, ?) con parámetros. El ID lo genera la base (IDENTITY).
5
AbstractJpaRepository.save() confirma con commit(). Si algo falla, rollback().

Vuelta de regreso: de la base a la pantalla

1
El controller llama cargar() → service.findAll() → Repository.findAll() → SELECT * FROM departamento.
2
SqlHelper.mapRow(ResultSet) convierte cada fila en un objeto Departamento.
3
Se guarda en ObservableList<Departamento> datos y se envuelve en FilteredList.
4
TableView usa PropertyValueFactory<>("numero") para pedir getNumero() y Celdas.chipEstadoDepartamento() para el chip.
5
El usuario ve la fila con su estado. El buscador dispara aplicarFiltro() y la tabla se actualiza sola.
Pregunta clave: “¿Qué datos recibe cada clase?” → El controller recibe texto y servicios; el service recibe objetos del modelo; el repository recibe entidades o IDs; el modelo recibe valores de campos; la base recibe parámetros SQL.

24.2 Cómo leer un archivo .java en 5 pasos

  1. Mira el package: dónde vive dentro del proyecto.
  2. Lee los import: de qué otras clases depende.
  3. Mira la firma: class X extends Y implements Z → herencia e interfaces.
  4. Busca los campos (datos) y el constructor (qué recibe).
  5. Lee los métodos: cada uno es una acción. Empieza por initialize() o on…().

24.3 Cómo leer un .fxml en 5 pasos

  1. Lee los <?import …?> del inicio: qué controles se usan.
  2. Busca fx:controller: qué clase Java maneja esa pantalla.
  3. Busca los fx:id: son los nombres que el controlador usa con @FXML.
  4. Busca los onAction="#metodo": qué método se ejecuta al hacer clic.
  5. Mira styleClass: engancha el diseño del app.css.
<Button fx:id="btnGuardar" text="Guardar" onAction="#onGuardar"
        styleClass="boton-primario"/>
// → el FXML dice: "botón Guardar, llámase btnGuardar, al clicar ejecuta onGuardar,
//    y ponle el estilo boton-primario del CSS"

24.4 Cómo leer el app.css en 5 pasos

  1. Un .clase (punto) aplica a todos los nodos con ese styleClass.
  2. Las propiedades siempre empiezan con -fx-, por ejemplo -fx-background-color.
  3. :hover es el efecto al pasar el mouse; :focused al seleccionar.
  4. Los colores pueden ser hexadecimales (#2563EB) o linear-gradient(...).
  5. -fx-effect: dropshadow(...) es la sombra de las tarjetas.
.boton-primario {
    -fx-background-color: #2563EB;   /* color azul */
    -fx-text-fill: white;            /* texto blanco */
    -fx-background-radius: 9;        /* esquinas redondeadas */
}
.boton-primario:hover { -fx-background-color: #1D4ED8; }  /* al pasar el mouse */
