2 Antes de empezar

  1. Instalar Git desde https://git-scm.com/download/win. El script lo verifica automáticamente.
  2. Crear un repositorio vacío en tu cuenta de GitHub. No inicialices con README ni .gitignore: déjalo completamente vacío.
  3. Copiar el archivo PREPARAR_EQUIPO.bat a tu PC (puede estar en cualquier carpeta).
  4. Si el repo plantilla es privado, pedir que te agreguen como colaborador en *Settings → Collaborators*.
  5. Tener tu usuario de GitHub y una PAT (token de acceso personal) o la credencial ya guardada por Git.
Repo vacío Si el repositorio destino ya tiene archivos, el push fallará. El script te ofrecerá opciones para resolverlo, pero lo más limpio es crear uno vacío.

3 Uso paso a paso

  1. Haz doble clic en PREPARAR_EQUIPO.bat. Se abrirá una ventana de comandos azul.
  2. Escribe la ruta destino, por ejemplo C:\Entrega\SysAlquileres, y presiona Enter.
  3. Pega la URL de tu repositorio: https://github.com/TU_USUARIO/TU_REPO.git.
  4. Presiona Enter en las dos preguntas opcionales para usar los valores por defecto.
  5. Si la carpeta ya existiera, responde s para eliminarla o n para elegir otra ruta.
  6. Espera a que termine. Verás los pasos [1/5] hasta [5/5].
  7. Presiona una tecla cuando aparezca Press any key to continue.
Resultado Tu repo de GitHub contendrá exactamente la misma estructura que el proyecto entregado.

5 Qué pasa internamente

git clone https://github.com/Yorlxx/SysAlquileres.git "C:\Entrega\SysAlquileres"
cd /d "C:\Entrega\SysAlquileres"

git remote rename origin plantilla
git remote add origin https://github.com/TU_USUARIO/TU_REPO.git

git push -u origin main

Después del push, tendrás dos remotos:

RemotoURLPara qué sirve
plantillaRepo originalConsultar actualizaciones futuras.

7 Si el push falla

Si tu repositorio no está vacío, el script muestra tres opciones:

OpciónQué haceCuándo usarla
s — unir historiasgit pull --allow-unrelated-histories y vuelve a subir.Cuando quieras conservar ambos contenidos.
f — forzargit push -f.Cuando sepas que puedes sobrescribir el repo.
c — cancelarDetiene el script.Cuando prefieras revisar antes.
Cuidado con forzar La opción f sobrescribe el historial remoto. Úsala solo en un repo propio que acabas de crear.

8 Credenciales y seguridad

  • El .bat no contiene contraseñas ni tokens.
  • Si GitHub solicita credenciales, usa tu usuario y una PAT, o la credencial guardada por Git Credential Manager.
  • No escribas tu contraseña dentro del script ni la compartas por chat.
  • Las credenciales reales de Supabase tampoco están en el repo: se configuran por variables de entorno.
# Si GitHub pide login, puedes autenticarte con:
gh auth login

# O dejar que Git Credential Manager guarde la credencial
git config --global credential.helper manager

9 Verificación final

Al terminar, ejecuta dentro de la carpeta destino:

git remote -v
git status -sb
git ls-files dist\*.apk

Deberías ver:

  • plantilla apuntando al repo original.
  • origin apuntando a tu repo.
  • ## main...origin/main sin mensaje de “ahead”.
  • La línea dist/SysAlquileres-Movil-v1.1.apk, confirmando que el APK está versionado.

10 Preguntas frecuentes

¿Necesito instalar Java o Android Studio?

No. Solo Git. El proyecto ya incluye el ZIP con JRE y el APK compilado.

¿Puedo ejecutar el .bat desde otra carpeta?

Sí. Solo necesitas indicar la ruta destino correcta.

¿Qué pasa si cierro la ventana antes de que termine?

Repite el proceso. Si la carpeta ya existe, responde s para recrearla.

¿El APK está realmente en GitHub?

Sí. Se agregó con git add -f y aparece en dist/SysAlquileres-Movil-v1.1.apk.

¿Y si el repo plantilla se vuelve privado?

Necesitas que te agreguen como colaborador en GitHub para poder clonarlo.
