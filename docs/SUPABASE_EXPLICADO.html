1 ¿Qué es Supabase?

La idea clave, sin tecnicismos.

🗄️ Es una base de datos en internet

Supabase ofrece una base PostgreSQL alojada en la nube. Es como tener el archivo de datos en un servidor, no en tu PC.

🔌 Se conecta por internet

Nuestro programa se conecta a una dirección (URL), con usuario y contraseña, igual que te conectas a un sitio web.

👥 Muchos usuarios, un solo dato

Al estar en la nube, escritorio y móvil pueden compartir la misma información.

Analogía H2 es como una libreta guardada en tu escritorio. Supabase es como una libreta en una biblioteca: la puedes consultar desde cualquier lugar, pero necesitas internet y una llave (credenciales) para entrar.

Orden de prioridad

  1. application.properties → trae H2 por defecto.
  2. Propiedades del sistema -Ddb.url=....
  3. Variables DB_URL, DB_USERNAME, etc.
  4. Variables SUPABASE_DB_* → ganan siempre.

6 DatabaseConfig.java, explicado fácil

Es la clase que prepara todo para que los repositorios puedan consultar.

  • 1. Lee application.properties desde los recursos.
  • 2. Sobrescribe con propiedades del sistema y variables de entorno.
  • 3. Normaliza la URL: agrega sslmode=require y prepareThreshold=0 si detecta Supabase.
  • 4. Crea el pool HikariCP: máximo 5 conexiones, timeout de 10 segundos.
  • 5. Ejecuta scripts solo si ddl.auto=true y seed.demo=true (en Supabase ambos son false).
  • 6. Muestra en consola el motor usado: [Supabase / PostgreSQL].
private static String normalizarUrl(String url) {
    boolean esSupabase = url.contains("supabase.co")
                      || url.contains("pooler.supabase.com");
    if (esSupabase && !url.contains("sslmode")) {
        url += "?sslmode=require";
    }
    if (url.contains("pooler.supabase.com")
        && !url.contains("prepareThreshold")) {
        url += "&prepareThreshold=0";
    }
    return url;
}

7 ¿Por qué SSL y prepareThreshold?

Dos detalles que parecen raros, pero son necesarios.

🔐 sslmode=require

Los datos viajan por internet. SSL los cifra para que nadie pueda leer la contraseña ni los alquileres en el camino.

⚙️ prepareThreshold=0

El pooler de Supabase trabaja en modo transacción y no guarda sentencias preparadas con nombre. Poner 0 evita el error “prepared statement already exists”.

Cómo explicarlo en clase “SSL es el candado del túnel. prepareThreshold es decirle a Java: no guardes la consulta con nombre, mándala siempre completa porque el intermediario no recuerda.”

SíntomaCausaSolución
“No fue posible abrir la base de datos”Falta internet o variable mal escrita.Revisa SUPABASE_DB_URL y la conexión.
“prepared statement already exists”Falta prepareThreshold=0.El código lo agrega solo; revisa la URL mostrada.
Error de certificado SSLFalta sslmode=require.El código lo agrega automáticamente.
“Connection is not available”Demasiadas conexiones o red lenta.HikariCP espera 10 s; revisa el pool y la red.

12 Guion listo para exponer

1. “Supabase es un PostgreSQL en la nube: nuestra base ya no está solo en la PC, está en internet.”

2. “Las credenciales no están en el código: se leen de variables de entorno SUPABASE_DB_*, que tienen prioridad sobre el H2 del archivo de propiedades.”

3. “Al arrancar, AppContext crea DatabaseConfig. Esta clase arma la URL, agrega SSL y prepareThreshold=0, y levanta un pool HikariCP de 5 conexiones.”

4. “Cuando el usuario guarda un pago, el controller valida en el service, el repository arma un SQL con parámetros ? y HikariCP presta una conexión para enviarlo a Supabase.”

5. “La respuesta se convierte otra vez en objetos Java y la tabla se actualiza. Por eso el mismo código funciona con H2 local o con Supabase.”

6. “Y lo comprobamos en la consola: dice [Supabase / PostgreSQL], y el panel de configuración muestra la URL activa.”

13 Preguntas frecuentes

¿La contraseña está en el código?

No. Está solo en la variable de entorno SUPABASE_DB_PASSWORD.

¿La app usa la API REST de Supabase?

La versión escritorio usa JDBC directo. La versión APK usa la API REST (PostgREST). Ambas llegan a la misma base.

¿Por qué no se ejecuta el schema.sql en Supabase?

Porque SUPABASE_DDL_AUTO=false y SUPABASE_SEED_DEMO=false: las tablas ya fueron creadas con database/supabase_schema.sql.

¿Qué pasa si se cae internet?

La app no puede consultar Supabase. Si quitas las variables de entorno, vuelve a H2 local y funciona sin internet.

¿Dónde está el modelo del architect?

En database/modelo-power-architect.architect, actualizado con 7 tablas.
